# d3d12_x technical debt

Serves `d3d12_x.dll` and `d3d12_xs.dll` (D3D12.X).

### Functional

- [Inventory](../../../core/libs/xdll/d3d12_x/Inventory.cpp) (d3d12_x) - `D3D12XboxCreateDevice`, `D3D12CreateDevice` and `D3D12GetDebugInterface` stop the title. D3D12.X interfaces have console-specific methods and layouts, so they cannot be forwarded to desktop `d3d12.dll`; the layer goes to Vulkan ([#4](https://github.com/Dark3581/AnyBox/issues/4)), with shaders from the shader store. `D3D12CreateDevice` and `D3D12GetDebugInterface` are declared with the desktop `d3d12.h` prototypes; the console prototypes are unverified
  Closes when: a title draws its first frame
- [DescriptorTable](../../../core/libs/xdll/d3d12_x/vulkan/DescriptorTable.cpp) (d3d12_x) - builds the descriptor hash table the translated shaders search (word 0 the mask, then ten words per slot: an eight-word T# or S# key, the bindless index, padding; FNV-1a over the key words; eight slots probed from the hash; a miss is index 0). The format is the one the translator's generated lookup reads, checked on a GPU by `anybox-pipeline-probe bindless`, not against a title. The slot comes from the low bits of the hash, which depend only on the low bits of each key word, so keys that differ only in high bits share slots and grow the table. The all-zero key cannot be stored and resolves to index 0
  Closes when: a title's descriptors are entered from its own descriptor writes and its shaders find them
- [BindlessSet](../../../core/libs/xdll/d3d12_x/vulkan/BindlessSet.cpp) (d3d12_x) - allocates the title layout's descriptor set and puts fallbacks at index 0 of every binding: zeroed 1x1 images (`R32_UINT` for the two bindings that declare it, 32-bit four-component float, uint or sint otherwise) and a nearest, clamp-to-edge sampler. What a title expects from a missing descriptor is unknown. The table buffer is host-visible and rewritten in place, and growing it replaces the buffer and rewrites binding 2, which has no update-after-bind flag, so neither may happen while the GPU uses the set
  Closes when: descriptor writes come from a title's calls and updates are ordered against GPU work
- [TitleBufferWindow](../../../core/libs/xdll/d3d12_x/vulkan/TitleBufferWindow.cpp) (d3d12_x) - reserves and commits one range below 4 GB, imports it as a single Vulkan buffer with `VK_EXT_external_memory_host` and gives the heap base (device address minus window start) that translated shaders add to the console addresses they read. Nothing allocates from it yet: which title allocations belong in it (option A on [#4](https://github.com/Dark3581/AnyBox/issues/4)) comes from a title's XMem and buffer calls. The memory is pinned and read by the GPU over PCIe, and the largest free range below 4 GB limits its size (2 GiB in the probe process on the test PC, 3 GiB not available)
  Closes when: a title's buffers and descriptor heaps are allocated from it and its shaders read them
- [PipelineState](../../../core/libs/xdll/d3d12_x/pso/PipelineState.cpp) (d3d12_x) - resolves a compute pipeline state description to its stored module and refuses any pipeline state flag and any node other than the first; the root signature is not consulted because every pipeline uses the title layout, and a cached pipeline blob is ignored. Nothing calls it until the device's `CreateComputePipelineState` exists
  Closes when: the device's `CreateComputePipelineState` creates its pipelines through it
- [PipelineLibrary](../../../core/libs/xdll/d3d12_x/vulkan/PipelineLibrary.cpp) (d3d12_x) - creates compute pipelines only, keeps every pipeline (and every refusal or failure) until the library is destroyed, and its run-time compile limit has no default: the caller picks it
  Closes when: graphics pipelines go through it and the device sets the compile limit from a configuration value
- [ShaderStore](../../../core/libs/xdll/d3d12_x/store/ShaderStore.cpp) (d3d12_x) - console shaders are looked up by the SHA-256 of the DXBC container in a store of modules translated ahead of time; that the bytes a title passes at pipeline creation equal the container as stored in its package is unverified, and nothing calls the store until pipeline creation exists
  Closes when: pipeline creation looks shaders up and a title's run shows its shaders found
- [VulkanBackend](../../../core/libs/xdll/d3d12_x/vulkan/VulkanBackend.cpp) (d3d12_x) - loads `vulkan-1.dll` from the system folder, creates an instance and reports each device's features, extensions, subgroup sizes and push constant limit; the feature list covers what translated shader stores have needed so far, not every Vulkan feature
  Closes when: a feature a title's store needs is reported and enabled by `VulkanDevice`
- [VulkanDevice](../../../core/libs/xdll/d3d12_x/vulkan/VulkanDevice.cpp) (d3d12_x) - picks a Vulkan 1.3 device that supports every shader feature a store names, enables exactly those plus the bindless layout's descriptor-indexing features and subgroup size control, and opens one graphics and compute queue; nothing calls it until `D3D12XboxCreateDevice` exists, and a feature name it does not know stops device creation
  Closes when: `D3D12XboxCreateDevice` creates its device through it
- [TitleLayout](../../../core/libs/xdll/d3d12_x/vulkan/TitleLayout.cpp) (d3d12_x) - set 0's twenty binding types and the 144-byte push constant range follow what the translated modules declare (checked against every module of one title's store by `shaders_layout`); the array sizes (8,192 2D sampled images, 2,048 samplers and so on) are AnyBox's choice, not the title's descriptor heap sizes, and nothing fills the push constants (the root-signature-to-user-SGPR mapping, heap base and code base come from the title's own calls)
  Closes when: the descriptor heap sizes and the root-signature mapping are taken from a title's calls
- [PipelineCompiler](../../../core/libs/xdll/d3d12_x/vulkan/PipelineCompiler.cpp) (d3d12_x) - creates compute pipelines only; graphics pipelines need the title's pipeline state (vertex input, render targets, blend, rasterizer), which only its pipeline creation calls give. A module whose subgroup size the device cannot require compiles without it, as the translator expects
  Closes when: graphics pipelines are created from a title's pipeline state descriptions
- [RootSignature](../../../core/libs/xdll/d3d12_x/RootSignature.cpp) (d3d12_x) - the serializers and deserializers forward to the host `d3d12.dll`. The serializers clear flag bits 24-31 of a 1.0 or 1.1 description first, because console callers set `0x03000000` there and the host rejects any of those bits; what the bits mean on the console is unknown, and the serialized root signature no longer carries them. Another description version stops with `AbxUnsupported`. The deserializers forward unchanged, so a blob that carries those bits is rejected by the host with its own error
  Closes when: the console meaning of flag bits 24-31 is known and the device that consumes the blob accounts for it
