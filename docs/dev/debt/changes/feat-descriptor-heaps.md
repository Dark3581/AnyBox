# d3d12_x

## add Functional

- [DescriptorSizes](../../../core/libs/xdll/d3d12_x/resources/DescriptorSizes.cpp) (d3d12_x) - the four descriptor handle increments are unknown and unset: translated shaders compute descriptor addresses with the console's increment compiled in, so the shader resource and sampler sizes must be the console's, and no title has given them yet. A heap whose size is unset is refused with that cause; the only checks are that a shader resource descriptor holds an eight-word image descriptor and a sampler descriptor four words, the key sizes the translator's lookup reads. To find them: the increment the title's code multiplies descriptor indices by around its `GetDescriptorHandleIncrementSize` call, or the index scaling of the scalar loads that read descriptor tables in its translated shaders
  Closes when: the device sets the sizes from a title, and its shaders read descriptors written at that stride
- [DescriptorHeap](../../../core/libs/xdll/d3d12_x/objects/DescriptorHeap.cpp) (d3d12_x) - `ID3D12DescriptorHeap`: shader-visible heaps sit in the buffer window at 64 KiB alignment, so their GPU handle is the address shaders read descriptors from, and other heaps in CPU memory; each slot has a CPU-side record of the Vulkan view or sampler it describes, and handles resolve to their heap through a registry. Whether the console aligns descriptor heaps differently, or places a buffer descriptor other than at the start of its slot, is unknown. Nothing creates heaps until the device's `CreateDescriptorHeap` exists
  Closes when: the device creates its heaps through it and a title's shaders read descriptors from them
- [DescriptorWriter](../../../core/libs/xdll/d3d12_x/objects/DescriptorWriter.cpp) (d3d12_x) - the device's view and sampler creation and descriptor copies: constant buffer and buffer shader resource and unordered access views write their buffer descriptors, null views write zeros, render target and depth-stencil views and samplers become Vulkan image views (cached per resource) and samplers (cached per description). Image and sampler descriptor words in a shader-visible heap, written directly or copied there, stop the title, because the console's image (T#) and sampler (S#) layouts are not sourced; in CPU-only heaps they are recorded and copied. Unordered access counters stop the title
  Closes when: the image and sampler descriptor layouts are sourced and written, so textures and samplers reach the bindless set through the descriptor hash table
- [CommandList](../../../core/libs/xdll/d3d12_x/objects/CommandList.cpp) (d3d12_x) - `SetDescriptorHeaps`, `OMSetRenderTargets` (render target and depth-stencil descriptors read at the call, as D3D12 does) and render target and depth-stencil view clears, with optional rectangles, work; the bound heaps and render targets are kept for draws that do not exist yet, and unordered access view clears stop the title
  Closes when: draws render into the bound targets and read the bound heaps
