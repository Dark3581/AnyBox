# d3d12_x

## change [records clears (render target and depth-stencil]

- [CommandRecorder](../../../core/libs/xdll/d3d12_x/commands/CommandRecorder.cpp) (d3d12_x) - records clears (render target and depth-stencil, whole or by rectangles, through dynamic rendering), buffer copies, copies between textures and placed footprints, texture copies, resolves, render passes over color and depth-stencil views, viewports (flipped with a negative height so D3D12's winding and y direction apply), scissors, the primitive topology with strip cut, blend factor, stencil reference, vertex and index buffers, pipeline binding, a push constant block of up to 144 bytes, draws, indexed draws and dispatches, with layouts taken from the D3D12 state the caller passes. A new texture is moved from `UNDEFINED` to its initial state's layout without clearing it, although D3D12 zeroes committed resources unless told not to. Depth-stencil textures copy plane 0 as depth (4 bytes per texel) and plane 1 as stencil (1 byte), and a read-only depth-stencil view renders in the read-only layout. Typed resolve formats, copies with a destination offset inside a footprint, patch list topologies and passes read-only for only one of the two planes (which need per-plane state tracking) are not supported; what goes in the push constant block (the title's root arguments as user registers, the heap base and the code base) is the caller's, and that mapping is not known yet. Nothing records with it until the device's command lists exist
  Closes when: a title's command lists record through it and its frames show the copied, cleared and drawn data
