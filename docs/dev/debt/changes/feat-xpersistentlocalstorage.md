## add Functional

- [XPersistentLocalStorage](../../../core/libs/xdll/xgameruntime/PersistentLocalStorage.cpp) (xgameruntime) - the title gets `%LOCALAPPDATA%\AnyBox\<TitleId>\PersistentLocalStorage\`, created on first use beside the `XGameSave` folder and outside it, so it never counts against the save quota; it ends in a backslash and has no `\\?\` prefix, which no documentation states, so the folder plus what the title appends can exceed `MAX_PATH` when `LOCALAPPDATA` is long; `<PersistentLocalStorage>` in `MicrosoftGame.config` is not read, following the documentation's PC behaviour (space is not provisioned and no entry is required), so the folder is neither reserved nor limited in size; every user of a title shares it; a missing `<TitleId>` or `LOCALAPPDATA` stops with `AbxUnsupported`, and a folder that cannot be created returns the Win32 error as an `HRESULT`
- [XPersistentLocalStorageGetPath](../../../core/libs/xdll/xgameruntime/PersistentLocalStorage.cpp) (xgameruntime) - the size from `XPersistentLocalStorageGetPathSize` and the value written to `pathUsed` count the terminating null, which the documentation's sample implies but does not state; a `pathSize` below that returns `HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER)` (the documented PC error) without touching `path` or `pathUsed`; a null `path` with a large enough size, or a null `pathSize`, stops with `AbxUnsupported`; the path is UTF-8, which no documentation states, so a title that passes it to ANSI Win32 calls breaks when `LOCALAPPDATA` holds non-ASCII characters and the code page is not UTF-8
  Closes when: the size and terminator are measured on a console title
- [XPersistentLocalStorageGetSpaceInfo](../../../core/libs/xdll/xgameruntime/PersistentLocalStorage.cpp) (xgameruntime) - `usedBytes` is the sum of the sizes of every file under the title's folder, walked on each call, with a subfolder removed during the walk counted as empty and a folder link (a directory reparse point) inside it stopping with `AbxUnsupported`; `availableFreeBytes` and `totalFreeBytes` are both the free bytes `GetDiskFreeSpaceExW` reports available to the calling user on the folder's volume, because the host allocates nothing the user could free into; `totalBytes` is `usedBytes` plus `totalFreeBytes`, the space the title holds plus the space it can still write; this mapping is AnyBox's, as the documentation describes the fields for a storage allocated on a console and also says persistent local storage is not implemented on PC; sizes are logical file sizes, not allocated clusters; a null `info` stops with `AbxUnsupported`
  Closes when: the values a PC runtime returns are measured
- [XPersistentLocalStoragePromptUserForSpaceAsync](../../../core/libs/xdll/xgameruntime/PersistentLocalStorage.cpp) (xgameruntime) - stops with `AbxUnsupported` for every input: there is no system UI to ask the user to free space, and the documentation only gives results for a user's choice (`S_OK` when the user took action, `E_ABORT` when they declined) and says the call should not be used on PC, so completing it with either result would invent a user's answer; `XPersistentLocalStoragePromptUserForSpaceResult` also stops with `AbxUnsupported` for every input, since no prompt can have started
  Closes when: a title that prompts is reported and its PC behaviour is measured
