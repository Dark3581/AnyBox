# xgameruntime technical debt

Serves `xgameruntime.dll`.

### Functional

- [XTaskQueue](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - the enum values (`Manual` 0, `ThreadPool` 1, `SerializedThreadPool` 2, `Immediate` 3; `Work` 0, `Completion` 1) and the `E_ABORT` result after termination follow the public XTaskQueue header in libHttpClient; not checked against a console title
  Closes when: measured on a console
- [XTaskQueueTerminate](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - pending and delayed callbacks are invoked with `canceled = true` on the terminating thread, not on their port's dispatcher; waiting from inside one of the queue's own callbacks stops with `AbxUnsupported`
- [XTaskQueueGetCurrentProcessTaskQueue](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - returns a new handle the caller closes; the default process queue is created on first use with thread-pool work and completion ports
- [XTaskQueueSubmitCallback](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - a null queue uses the process task queue; with none set it stops with `AbxUnsupported`
- [XGameGetXboxTitleId](../../../core/libs/xdll/xgameruntime/Runtime.cpp) (xgameruntime) - reads `<TitleId>` from `MicrosoftGame.config` beside the executable; stops with `AbxUnsupported` when it is missing
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - return codes follow the public libHttpClient `AsyncLib.cpp`, `AsyncBlockTests.cpp` and `pal.h`, not a console: `XAsyncBegin` on a block in use returns `E_INVALIDARG`; a null queue with no process task queue returns `E_NO_TASK_QUEUE` (`0x800701AB`) and an allocation failure `E_OUTOFMEMORY`, both also left as the block's status; a failed `Begin` op completes the call with its error; `XAsyncSchedule` while work is already scheduled returns `E_UNEXPECTED`, also after the task queue refused the work, which leaves it marked scheduled; after a failure it returns that failure, and after a success without payload, or once the result was retrieved, returns `E_INVALIDARG`; a `DoWork` that returns success without completing completes with `E_UNEXPECTED`, and scheduled work is skipped once the call completed without payload; a second `XAsyncGetResult` returns `E_ILLEGAL_METHOD_CALL`, and a wrong identity, null buffer or too small buffer returns `E_INVALIDARG` or `E_NOT_SUFFICIENT_BUFFER` and discards the result; `XAsyncRun` work cannot be canceled
  Closes when: measured on a console title
- [XAsyncCancel](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - invokes the provider's `Cancel` op only while the call's status is `E_PENDING`, following `XAsync.h` ("does nothing if the call has already completed"); the reference `AsyncLib.cpp` still invokes it on a call that completed with a payload not yet retrieved
  Closes when: measured on a console title
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - the provider's `Cleanup` op runs once, when the last reference to the call is released (after the op or completion callback that ended it, or after `XAsyncGetResult`), never during another op; the reference can run it earlier, at the end of the `DoWork` that completed the call
  Closes when: the op order is measured on a console
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - when the completion callback cannot be queued because the call's task queue was terminated, it stops with `AbxUnsupported`, naming the XAsync export on the stack (`XAsyncComplete`, or `XAsyncBegin` for a failed `Begin` op), or `XAsyncComplete` when the completion starts from a task queue callback (work canceled by `XTaskQueueTerminate`, or work whose result is not `E_PENDING`); the reference holds termination until outstanding calls complete, which AnyBox's XTaskQueue cannot do
  Closes when: XTaskQueueTerminate waits for outstanding async calls
- [XAsyncBegin](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - does not return `E_ABORT` up front when the block's queue is already terminated, as the reference does: XTaskQueue exposes no termination state, so the `Begin` op runs and `XAsyncSchedule` returns the queue's `E_ABORT`; when the `Begin` op returns that failure, `XAsyncBegin` returns `S_OK` and the call completes with `E_ABORT` if the block has no completion callback, and stops with `AbxUnsupported` in `XAsyncBegin` if it has one
  Closes when: XTaskQueueTerminate waits for outstanding async calls
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - a null async block, provider, work callback or result size pointer stops with `AbxUnsupported`, except `XAsyncComplete` with `E_PENDING`, which returns first; a block whose internal bytes are all zero behaves as a zeroed block in the reference: `XAsyncCancel` and `XAsyncComplete` do nothing, `XAsyncGetStatus`, `XAsyncGetResultSize` and `XAsyncGetResult` return `S_OK` with a size of 0, and `XAsyncSchedule` returns `E_INVALIDARG`; on any other block that no call owns, `XAsyncCancel` and `XAsyncComplete` do nothing, as in the reference, and `XAsyncGetStatus`, `XAsyncGetResultSize`, `XAsyncSchedule` and `XAsyncGetResult` stop with `AbxUnsupported`, because the reference returns whatever its status field holds
- [XAsyncGetStatus](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - waiting from inside the call's own completion callback returns the status at once instead of waiting for that callback to return
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - a completion callback still queued when its task queue is terminated runs the title's callback on the terminating thread, as the reference does for canceled completions
- [XGameRuntimeIsFeatureAvailable](../../../core/libs/xdll/xgameruntime/Runtime.cpp) (xgameruntime) - returns `true` for every feature in the public `XGameRuntimeFeature.h` (2610), as a console runtime does, although many of their exports are still stubs that stop the title; values above `XGameStreaming` return `false`
- [XGameRuntimeInitializeWithOptions](../../../core/libs/xdll/xgameruntime/Runtime.cpp) (xgameruntime) - only `XGameRuntimeGameConfigSource::Default` is supported; `Inline`, `File` and null options stop with `AbxUnsupported`
  Closes when: the runtime can read a game config from a string or another path
- [XThreadSetTimeSensitive](../../../core/libs/xdll/xgameruntime/Thread.cpp) (xgameruntime) - only records the flag per thread; AnyBox functions that can block do not check it, and `XThreadAssertNotTimeSensitive` on a time-sensitive thread stops with `AbxUnsupported` because the console's reaction is unknown
  Closes when: the console's behaviour for a blocking call on a time-sensitive thread is measured
- [XPackageGetCurrentProcessPackageIdentifier](../../../core/libs/xdll/xgameruntime/Package.cpp) (xgameruntime) - always returns `E_GAMEPACKAGE_APP_NOT_PACKAGED` without writing the buffer, consistent with `XPackageIsPackagedProcess` returning `false`
- [XGameSave](../../../core/libs/xdll/xgameruntime/GameSave.cpp) (xgameruntime) - containers are stored as one file each, `<container name with / as %>.xgs`, in `%LOCALAPPDATA%\AnyBox\<TitleId>\XGameSave`; there is no cloud sync, `needsSync` is always `false`, and the requesting user, `configurationId` (only checked for null) and `syncOnDemand` are ignored, so every user of a title shares one set of saves; a missing `<TitleId>` or `LOCALAPPDATA` stops with `AbxUnsupported`
  Closes when: XUser is implemented and saves are kept per user
- [XGameSave](../../../core/libs/xdll/xgameruntime/GameSave.cpp) (xgameruntime) - signatures, structures, error codes, the container name rules (`E_GS_INVALID_CONTAINER_NAME`), the 16 MiB update limit (`E_GS_UPDATE_TOO_BIG`), the 256 MiB per-user quota (`E_GS_QUOTA_EXCEEDED`) and `E_GS_HANDLE_EXPIRED` for an update used after it was submitted follow the public GDK documentation, not a console; the quota counts blob bytes only, and container and blob names match case-insensitively
  Closes when: measured on a console title
- [XGameSave](../../../core/libs/xdll/xgameruntime/GameSave.cpp) (xgameruntime) - behaviour the documentation does not state: a null pointer argument returns `E_INVALIDARG`, as does an empty blob name or a second write or delete of one blob in an update; a change or a second submit while an asynchronous submit of the same update is pending returns `E_GS_HANDLE_EXPIRED`, and a submit that fails leaves the update open for another submit; deleting a missing blob or container succeeds; `XGameSaveGetContainerInfo` on a missing container returns `S_OK` without calling back; a null display name in `XGameSaveCreateUpdate` keeps the stored one; `XGameSaveReadBlobData` with null `blobNames` and a count of 0 reads every blob; the read buffer holds the `XGameSaveBlob` array followed by each blob's name and data, and a buffer that is too small returns `E_GS_PROVIDED_BUFFER_TOO_SMALL`; the blob name length limit is not enforced; host I/O failures return `E_GS_OUT_OF_LOCAL_STORAGE` for a full disk and the Win32 error otherwise
  Closes when: measured on a console title
- [XGameSave](../../../core/libs/xdll/xgameruntime/GameSave.cpp) (xgameruntime) - a container name over 251 characters (the documented limit is 256), a blob over 4 GiB, or a file in the save folder that AnyBox did not write stops with `AbxUnsupported`
- [XSystemGetConsoleId](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - always returns `00000000.00000000.00000000.00000000.00`, the value the GDK documentation gives for PC and for the retail sandbox; a buffer smaller than `XSystemConsoleIdBytes` (39) returns `HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER)` without touching `consoleIdUsed`; `consoleIdUsed` receives 39, counting the terminator; a null `consoleId` stops with `AbxUnsupported`; not checked against a console title
  Closes when: the size reported in `consoleIdUsed` and the short-buffer behaviour are measured on a console
- [XSystemGetDeviceType](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - derived from `TargetDeviceFamily` of the first `<Executable>` in `MicrosoftGame.config`, not from the host: `Scarlett` reports `XboxScarlettAnaconda`, `XboxOne` or an `<Executable>` without the attribute reports `XboxOneX`, `PC` reports `Pc`; a missing config, a config without `<Executable>` or any other value stops with `AbxUnsupported`; the top model of each family is reported whatever the host hardware, not checked against a console title
  Closes when: a console title's reaction to the other models of its family is measured
- [XPackageIsPackagedProcess](../../../core/libs/xdll/xgameruntime/Package.cpp) (xgameruntime) - always returns `false`: a relinked title started from a folder has no package identity on the host
- [XSystemGetXboxLiveSandboxId](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - always returns `RETAIL`, the value the GDK documentation gives for the retail environment and when no sandbox is stored on the device; a development sandbox set on the PC is not read; a buffer smaller than `XSystemXboxLiveSandboxIdMaxBytes` (16) returns `HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER)` without touching `sandboxIdUsed`; `sandboxIdUsed` receives 7, counting the terminator; a null `sandboxId` stops with `AbxUnsupported`; not checked against a console title
  Closes when: the size reported in `sandboxIdUsed` is measured on a console, and a title that needs a development sandbox is reported
- [XTaskQueueIsEmpty](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - not in the public GDK 2610 headers or the runtime's export list; kept for internal callers, no title imports it

### Silent stubs

- [XGameRuntimeInitialize](../../../core/libs/xdll/xgameruntime/Runtime.cpp) (xgameruntime) - returns `S_OK` without starting any service; nothing in AnyBox needs initialization yet
